# NSSM Native 2.25.0-beta.2

This prerelease adds 34 fixes since beta.1, covering child supervision, service controls, log rotation and configuration editing. For most 64-bit Windows installations, download the x64 Release ZIP. x86 Release, diagnostic builds with matching symbols, and a pinned source archive are also available. [Downloads](https://github.com/existical/nssm-native/releases/tag/v2.25.0-beta.2)

## Changes for operators

- NSSM retries a temporary relaunch failure, lets STOP interrupt the wait and registers the exit monitor before reporting RUNNING. It confirms forced termination before reporting a successful stop.
- Relative log paths resolve against the application's working directory. Two paths to the same output file share a writer. After an online rename, the logger recreates the active file and keeps writing.
- Rotate/Post waits for successful rotation of every participating output stream. A quiet stream can delay the hook until its next line boundary. Shutdown cancels a pending rotation.
- Unrelated GUI edits preserve raw paths, registry types and advanced rotation settings. Failed saves report an error and keep the entered values available for retry. Some earlier optional changes may already have been written.
- The CLI can repair a missing Application setting on a registered wrapper. Incomplete backups and unsupported native-service exports return failure. Clone exports leave the display name available for the destination. Use this beta's CLI to replay exports that specify a literal hook registry type.

The fix register maps NSSM-038 through NSSM-071 to specific changes and tests. [Fix register](https://github.com/existical/nssm-native/blob/v2.25.0-beta.2/docs/fixes/november-supervision-and-configuration.md)

## Validation and upgrade

The implementation passed all 148 standard x86/x64 Debug and Release tests, 37 AddressSanitizer tests and all five live Windows service suites. A Windows 11 VM completed ten additional lifecycle repetitions and a legacy-to-candidate-to-legacy upgrade and rollback. The report identifies the executable hashes and records the outstanding compiler warnings and manual GUI coverage limits. [Verification report](https://github.com/existical/nssm-native/blob/v2.25.0-beta.2/docs/reviews/2026-11-19-post-implementation-review.md)

Before upgrading, save the running executable and export each service's configuration. Stop the service and confirm its application has exited, then replace the executable at the same path. Check application readiness, logs, restart and shutdown with your workload. Keep the previous binary and configuration available for rollback.

The executables are unsigned. Verify the ZIP's SHA-256 against the published checksums and run `nssm.exe version` to confirm `2.25.0-beta.2` and the expected architecture. Use the supplied source ZIP to rebuild with the recorded version identity.
