# NSSM Native 2.25.0

NSSM Native 2.25.0 is the first stable release of this continuation of NSSM. It includes CONT-001 through CONT-005 and NSSM-001 through NSSM-071 from the beta series. The [fix index](https://github.com/existical/nssm-native/blob/v2.25.0/docs/fixes/README.md) describes the individual changes.

## Downloads

Use the [x64 Release ZIP](https://github.com/existical/nssm-native/releases/download/v2.25.0/nssm-native-v2.25.0-x64-Release.zip) for 64-bit Windows or the [x86 Release ZIP](https://github.com/existical/nssm-native/releases/download/v2.25.0/nssm-native-v2.25.0-x86-Release.zip) for 32-bit Windows. Both include matching debugging symbols. The executables are unsigned. Compare the ZIP's SHA-256 with the entry in `RELEASE-ASSETS-SHA256SUMS.txt`, then run `nssm.exe version` to confirm the version and architecture.

## Changes since beta.5

- Saving a service description preserves configuration another administrator changed while the editor was open, including the executable, startup mode, dependencies, environment and restart delay. Conflicting edits to the same launch field prompt the operator to reopen the editor.
- When Windows rejects a save, NSSM attempts to restore the registry values, hooks and description it already changed. It identifies settings that need attention if restoration fails. A newly granted service logon right can remain on the account after a rejected account change.
- Environment lookups, updates and removals use Windows case comparisons for non-ASCII variable names. Export and replay preserve the order of duplicate assignments.

## Compatibility and upgrade

Windows 11 acceptance covered a stateful Windows PowerShell worker, service start and stop, crash recovery, interactive editing, LocalSystem and virtual service accounts, and upgrade and rollback against a pinned legacy build. Two operators explicitly editing the same non-launch setting can still overwrite each other's changes. Verify the service account and workload used by your deployment before rollout. [Windows 11 review record](https://github.com/existical/nssm-native/blob/v2.25.0/docs/reviews/2026-11-24-final-edit-review.md)

Before replacing an installed wrapper, record its executable path, version and checksum, export its configuration, and keep the previous executable and application data available for rollback. [Upgrade and rollback procedure](https://github.com/existical/nssm-native/blob/v2.25.0/docs/releases/upgrade-rehearsal.md)
