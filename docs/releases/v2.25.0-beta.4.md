# NSSM Native 2.25.0-beta.4

This prerelease fixes a race that could make `nssm start` time out after two seconds while the service was still starting.

For 64-bit Windows, download the x64 Release ZIP. Use the x86 Release ZIP for 32-bit Windows. Each binary ZIP includes matching debugging symbols. The executables are unsigned. Compare the download's SHA-256 hash with `RELEASE-ASSETS-SHA256SUMS.txt` and run `nssm.exe version` to confirm the version and architecture. [Download x64 Release](https://github.com/existical/nssm-native/releases/download/v2.25.0-beta.4/nssm-native-v2.25.0-beta.4-x64-Release.zip)

## Changes for operators

- NSSM advances the Service Control Manager checkpoint when its handler registers and as startup progresses. Clients receive the wait hint for the current phase of startup or shutdown.
- Removing the last `AppEnvironment` variable now preserves an empty replacement environment. Use `nssm reset <service> AppEnvironment` to restore inheritance. NSSM rejects malformed additions and skips an application or hook launch if it cannot apply the configured environment.
- When an automatic log rotation fails, NSSM continues writing and increases the interval between retries up to 60 seconds. An explicit rotation request bypasses the retry delay.
- The GUI checks the full application path, working directory, arguments and description before saving. It also releases localized strings used in tabs, hook controls and the file picker. Installation and editing report when the service manager rejects delayed automatic startup.
- Headless CLI usage errors go to redirected stderr. Registry diagnostics report the error from the failing operation, and event-source registration closes its registry handle.
- Package verification checks that every file is covered by the checksum inventory and that the manifest references top-level ZIP archives from that inventory.

The review records the Windows 11 service tests, AddressSanitizer results and remaining static-analysis warnings. [Review and test results](https://github.com/existical/nssm-native/blob/v2.25.0-beta.4/docs/reviews/2026-11-20-beta3-review.md)

## Upgrade and rollback

Back up the existing executable and export the service configuration. Stop the service, confirm its application has exited, then replace the executable at the same path. Check application readiness, logs and shutdown under the configured service account. Retain the previous executable and configuration for rollback. [Upgrade rehearsal](https://github.com/existical/nssm-native/blob/v2.25.0-beta.4/docs/releases/upgrade-rehearsal.md)
