# NSSM Native 2.25.0-beta.1 candidate

Status: unpublished beta candidate, prepared on 2026 November 3. The local
annotated tag is `v2.25.0-beta.1`; public tag/release publication is a later
step. This is the first proposed release of the NSSM Native continuation.
It is not an original upstream NSSM release or a stable-support declaration.

All 37 identified review and acceptance fixes and CONT-001 through CONT-005
are included. They remain fixed/implemented but unreleased until matching
assets and the tag are publicly published. Exact candidate identity is the
full source commit and tag in the supplied build-info.json; the executable
version alone is insufficient. The runtime implementation is unchanged from
merged master `f0fdfdd5d3f3762bd825694a3288e9fd99aa07e6`. This preparation updates
documentation and the unversioned-source fallback VERSION to 2.25.0, and adds
the changelog/contributing guide to binary ZIPs alongside the existing docs.

## Behavior to review when upgrading

- Empty environment entries no longer skip the following entry. Hook command
  quoting and stored literal environment expressions survive configuration edits.
- Startup waiting is separate from restart throttling. START/STOP/PAUSE/CONTINUE
  report genuine failures and have documented polling limits. A CLI timeout
  does not cancel the service operation, and RUNNING does not prove application
  readiness. See the exact [control policies](../usage.md).
- Malformed or oversized settings, invalid numeric input and incomplete exports
  report failures. Scripts that ignored exit codes should check their results.
- Offline rotation now applies its configured size, age and delay correctly.
  Review workarounds for the old argument-order defect; logger shutdown retains
  bounded drain/cancellation behavior, not unlimited delivery guarantees.
- Startup/STOP and exit cleanup share protected ownership. Process cleanup
  verifies identities; hook/logger resources stay owned until completion or
  the documented cleanup policy applies.

The command-line interface and registry schema are retained. Existing services
do not need reinstalling solely to replace NSSM. Application data migrations
are outside this wrapper update and require the application's own rollback plan.

Each binary ZIP includes nssm.exe, matching nssm.pdb, license, README, changelog,
contributing guide, documentation and an inner build-info.json. Release builds
use the static CRT. The version command
must report `NSSM 2.25.0-beta.1`, followed by architecture, optional debug marker
and commit-based date. The embedded numeric version is 2.25.0.0 with the
prerelease flag; the text file/product versions retain the beta qualifier.

These packages are unsigned. SHA-256 verifies file identity, not publisher
authentication. Use the supplied source ZIP for rebuilding this candidate;
an automatically generated GitHub source archive lacks source-info.json and
cannot establish the exact beta identity. The fallback VERSION is not release
provenance. See [packaging instructions](README.md) for clean-tree requirements.

During preparation, the beta tag exists only locally. Ordinary PR CI builds
the same source commit using the public tag history, so its commit-labelled
packages have a different version. They must not be renamed into beta assets.
The supplied beta manifests and their evidence identify the actual beta builds.

## Validation and remaining acceptance

The merged runtime baseline passed [CI 41643001489](https://github.com/existical/nssm-native/actions/runs/41643001489):
42 groups in x64 Release, 37 in each other configuration, ten consecutive
wrapped lifecycle repetitions, and clean-source packaging/verification.
[B15's committed evidence](../reviews/b15-validation.md#post-merge-validation)
records actual executable hashes and the legacy-to-candidate-to-legacy trial.
The legacy comparison rebuilt unchanged source with the current compiler; it
did not execute an official distributed legacy binary.

The locally tagged beta package procedure runs all 37 unprivileged groups in
each of four configurations, checks versions/architecture/resources, and
verifies archive/source identity and checksums. Its actual results and toolchain
are retained with the packages. Service-level tests run separately on disposable
elevated Windows Server 2022 CI; local beta packaging does not operate services.
PR validation links and final candidate commit are recorded in the preparation
PR without inventing a self-referential hash in these source notes.

QRScanner application acceptance and the recommended 24-48-hour run are still
pending. Use the [acceptance checklist](qrscanner-beta-acceptance.md), including
the actual installed legacy binary, application readiness, representative work,
controlled restart, reboot and rollback. Automated PowerShell-worker acceptance
does not replace that trial. Manual GUI/accessibility, domain accounts, older
Windows, large process trees and high hook concurrency also remain unvalidated.
The x86 CI build runs on a 64-bit host; it is not a test of a 32-bit Windows OS.
Do not advertise untested configurations as supported on the strength of builds.

## Publication conditions

Review this candidate and its concrete packages; merge the preparation PR and
retain the candidate tag's exact commit. Record application acceptance or make
an explicit decision about any remaining beta limitations. If source changes,
prepare a new candidate version instead of moving the existing tag.

Publish as a GitHub **prerelease**, upload the complete matching package set and
test evidence, and verify downloaded checksums/links. Only then set the included
fix records' first release to v2.25.0-beta.1. A stable release needs broader
application, account, GUI and advertised Windows-version acceptance.
