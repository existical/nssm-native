# NSSM code review, 21 November 2026

Reviewed revision `032a954ee6ef093a5ede70ad21e832f7fc829e45` on `review/beta4-followup`. The most consequential finding is that a rejected GUI edit can still disable an existing service. The other four findings affect configuration preservation, console creation, logging diagnostics and hook editing.

All five findings have since been fixed in the working tree. The findings and their source line numbers below describe the reviewed revision. [Fixes and regression coverage](#fixes-applied-after-this-review)

## 1. High — A rejected dependency edit can still disable the service

When an operator changes the startup type and enters a nonempty dependency list, `edit_service()` first commits the startup type, account and display name through `ChangeServiceConfig`. Only afterward does NSSM resolve and validate the dependencies. A missing service or overlong name causes the edit to return error 5. The first SCM change remains in effect. An operator who cancels the dialog after seeing the error can leave a service disabled and discover it at the next restart. [First SCM write and subsequent dependency update](../../src/service.cpp#L1453) · [Dependency validation](../../src/service.cpp#L608)

A test double recorded a successful `SERVICE_DISABLED` write before the production edit routine rejected an overlong dependency and returned 5. This exercised the existing-service edit path without changing an installed service.

**Fix and regression check.** Resolve the full dependency list before granting account rights or changing service configuration. Pass the canonical list in the same SCM call as the startup type, account and display name. Test both an invalid dependency and an SCM-rejected dependency, then query the service and verify that all original fields survived.

## 2. Medium — An unrelated GUI save can erase a valid priority change

Open a service in the editor with normal priority, change its priority to High from a second administration session, then save an unrelated field in the editor. The editor writes its old Normal selection by deleting `AppPriority`. Both writers can report success, and the next launch uses normal priority. There is a second route to the same loss. Opening a service with an unrecognized priority DWORD substitutes Normal, and saving removes the original value. [Priority loading](../../src/registry.cpp#L896) · [GUI selection on save](../../src/gui.cpp#L821) · [Registry deletion](../../src/registry.cpp#L157)

An isolated registry fixture exercised the editor's load and save functions. It confirmed deletion of a valid `HIGH_PRIORITY_CLASS` written between the two calls. It also confirmed deletion of a pre-existing DWORD of 12345 following a successful load and save.

**Fix and regression check.** Track whether the operator changed the priority control and write it only on an explicit change. Preserve unreadable or unrecognized values on unrelated saves. Cover both observations above and an intentional High-to-Normal reset, which should still delete the override.

## 3. Medium — `AppNoConsole=1` can still give a console application a window

NSSM detaches from its console before launching the application. With `AppNoConsole=1`, it omits `CREATE_NEW_CONSOLE` but supplies no flag to suppress the child's console window. This defeats the documented setting for console executables. [Detachment and child launch](../../src/service.cpp#L2045) · [Documented setting](../upstream/README.txt#L279) · [Windows process creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)

A detached Windows parent launched the same console executable three times with normal priority. The parent had no console window. The child reported a non-null `GetConsoleWindow()` with NSSM's no-console flag combination and with `CREATE_NEW_CONSOLE`. It reported a null handle with `CREATE_NO_WINDOW`. The probe measured handle presence, not visibility on a service desktop.

**Fix and regression check.** Select `CREATE_NO_WINDOW` for the no-console case. Exercise a real console child under both settings and verify redirected stdout and stderr still work when the console is suppressed.

## 4. Medium — A fatal logger read can stop output without logging the cause

Timestamping and hook output sharing can each require a logging pipe with online rotation disabled. If the worker hits an unexpected fatal read error in that configuration, `try_read()` skips the read-failure event because rotation is offline. The worker then closes the pipe and log file and exits with code 2. Operators see output stop without the event identifying the affected path and Windows error. [Pipe selection](../../src/registry.cpp#L927) · [Event suppression](../../src/io.cpp#L790) · [Worker exit](../../src/io.cpp#L955)

With timestamping enabled, a worker fixture supplied the same `ERROR_ACCESS_DENIED` read failure twice. The worker returned 2 in both cases. It emitted one `NSSM_EVENT_READFILE_FAILED` with online rotation enabled and zero with it disabled.

**Fix and regression check.** Use shutdown state and the read result to decide whether to suppress a diagnostic. Check that an unexpected read failure emits exactly one event in each active rotation mode, while producer EOF and deliberate shutdown stay quiet.

## 5. Low — A failed hook-field refresh can save a command under the wrong action

When switching hook actions, the editor selects the new draft even if writing its command to the edit control fails. The control can still show the previous action's text. The next edit is captured against the newly selected action, so saving can install a command for the wrong lifecycle event. [Hook selection](../../src/gui.cpp#L526) · [Edit notification](../../src/gui.cpp#L1273) · [Persistence](../../src/gui.cpp#L539)

A Windows dialog fixture rejected one `WM_SETTEXT` while switching from Start/Pre to Start/Post. The field still displayed the pre-start command. Appending one argument and saving stored that entire command and argument under Start/Post.

**Fix and regression check.** Verify that the control displays the requested command before binding it to the new draft. On failure, restore the previous selection or disable hook editing until a refresh succeeds. Repeat the injected failure and verify that neither action changes in the registry.

## Review scope and verification

The source review covered CLI and configuration export, service installation and control, child and hook lifecycles, account and environment handling, registry and GUI editing, stream redirection and rotation, and the build, packaging and test entry points. The five findings above identify concrete failure conditions.

The unmodified Windows suite passed all 37 tests in each of x86 Debug, x86 Release, x64 Debug and x64 Release (148 test executions). These tests run independently of the targeted checks described below.

The four instrumented fixture groups ran on x64 Release against a separate archive of the reviewed revision. Only the test fixtures in that copy were modified. The SCM check used a test double, the priority and hook checks used an isolated test registry, and the logging check injected a read failure into the production worker. The console check used real Windows child processes outside the SCM.

Earlier validation records cover MSVC analysis, AddressSanitizer, candidate packaging, and five elevated Windows 11 SCM and upgrade suites for production commit `06279bf`. The two subsequent commits through the reviewed revision changed documentation. Those earlier runs are separate from this review's local checks. [Prior validation record](2026-11-21-export-hooks-and-streams.md#verification)

## Fixes applied after this review

- [x] **Dependency edits.** NSSM resolves the dependency list before account-rights handling and submits the resolved list, startup type, account and display name in one SCM call. Both the CLI dependency setter and the editor use the same resolver. The regression covers lookup failure, rejection by the SCM and a successful combined edit. [Dependency tests](../../tests/dependencies.cpp)
- [x] **Priority edits.** The editor records an explicit priority selection. Saving an untouched field now preserves the stored priority, including a concurrent write or an unrecognized DWORD. An explicit selection of Normal still clears the override. [Editor tests](../../tests/install_gui.cpp)
- [x] **Console creation.** The no-console option now requests `CREATE_NO_WINDOW`. The live lifecycle test observes the console handle in the wrapped executable and checks its redirected output under both settings. [Lifecycle test](../../tests/lifecycle_live_cases.h)
- [x] **Logging diagnostics.** An unexpected fatal pipe read emits the read-failure event in offline, online and pending-rotation modes. Regression checks also cover producer EOF and deliberate draining. [Logging tests](../../tests/log_bytes_cases.h)
- [x] **Hook selection.** The editor checks the displayed command before enabling editing or binding the new draft. A failed refresh leaves the field and Browse button disabled until a successful selection. The regression checks registry contents after a failed refresh and verifies recovery. [Hook editor tests](../../tests/install_gui.cpp)
